## (완료) R22 배치로 모니터 전환 + 실장비(LIVE) 동기화 (화면·서버·프로토콜·가짜 장비)

### Context
- **사용자 요청**: R22 센서 문서(MD와 같은 내용의 HTML, 그림 4장 포함)를 기준으로 모니터를 바꾼다. 장소는 **투입·검사·UV·불량 4곳**이 되고, 센서를 단 로봇이 **스스로 움직이며**, 화면은 **실제 움직임과 동기화**된다.
- **사용자 결정**
  - Mega가 공정을 돌리고 PC는 표시한다.
  - 이번 범위는 화면·서버·프로토콜·가짜 장비까지다. Mega 펌웨어는 다음 단계에서 이 프로토콜에 맞춰 만든다.
  - PC는 Mega에 원점·시작·일시정지·재개·정지·알람 해제만 보낸다(모두 확인 창을 거친다).
  - 불량품은 ③에 넣고 다음 웨이퍼로 넘어간다.
  - UV 조사 시간은 아직 모른다 → 10 s로 가정한다.
- **사용자가 설명한 흐름**
  1. 대차에서 카세트를 꺼내 ① 투입에 놓는다.
  2. 슬롯 1→5(아래부터) 순서로 웨이퍼마다 다음을 한다.
     - 집기 → ② 검사(촬영, OK/NG, 치우침 δr·δθ) → 보정해서 다시 집는다.
     - NG면 ③ 불량에 위 슬롯부터 넣는다.
     - OK면 θ0 UV 탑에 넘기고 → UV를 켰다 끄고 → 다시 집어 → ① 원래 슬롯에 되돌린다.
  3. 5장이 끝나면 ① 카세트를 들어 원래 대차 자리에 놓고, 대차가 움직인다.
- **R22 문서의 숫자**
  - RX: ① 73, ②·③ 51, UV·대차 85
  - ZC: 선회 105, UV 넣기 121.5, UV 아래 구간 113.5~121.5, 소프트 상한 245
  - 옆길 θ180↔220은 RX ≤ 2에서만 지난다.
  - Sharp 환산: Z 거리 = 349.1 − ZC, R 거리 = 104 + RX
  - θ 자리 센서 5개(0·60·120·180·270), 각 자리 ±1.65° 안에서만 LOW
  - ToF 2개(TOF-IN ①, TOF-NG ③)는 카세트 유무만 본다.
  - S4는 P3·U5·U7·R5에서 확인한다.
  - UV 켜기 조건 7가지
  - 슬립링 18회로

### 내가 정한 해석 (승인 때 확인받을 가정)
1. **① 옆길은 모든 슬롯에 쓴다.**
   - ① 도크가 22 mm 바깥으로 나가서, RX ≤ 2인 빈 포크는 슬롯 사이를 자유롭게 오르내린다.
   - 하지만 **웨이퍼를 든 채로는** 아래 슬롯 웨이퍼와 27 mm 겹친다(R9 몸체 치수로 계산).
   - 그래서 웨이퍼를 든 Z 이동은 θ220(옆길)으로 비켜서 한다. 문서의 "ZC 205 슬롯 5 옆길"은 그중 한 예로 본다.
   - 옆으로 비킬 때 카세트 옆 레일과 간섭하는지는 [불명]이다(R22 도면 필요).
2. **θ는 슬립링이라 계속 돌 수 있다.**
   - 카세트를 들고 ① 180 ↔ 대차 270(=−90)을 오갈 때는 220 옆길을 지나는 90° 짧은 길로 간다.
   - 긴 길(120·60·0 위)로 가면 ③ 카세트와 부딪힌다(계산 확인).
3. **원점은 R을 먼저 뺀다(R → Z → θ).**
   - 문서는 Z를 먼저 적었다. 하지만 포크가 카세트 안에 있을 때 Z를 먼저 움직이면 긁는다. R9에서 정한 순서를 따른다.
   - θ는 −쪽으로 5°/s로 돌다가, 95° 안에서 처음 LOW가 난 센서를 그 자리로 삼는다. LOW가 없거나 2개 이상이면 멈춘다.
4. **대차는 카세트를 1~4개 싣고 온다(기본 4개, R9 영상 기준)[가정].**
   - 받침 하나마다 카세트를 내려 처리하고, 같은 받침에 되돌린 뒤 대차가 다음 받침으로 옮긴다.
   - 다 끝나면 대차가 떠나고 새 대차가 온다.
   - 시뮬 도구 '다음 대차 맵'에서 카세트를 1개로 하면 "한 번 오고 떠나는" 흐름이 된다.
5. **판정 알고리즘은 [미구현]이다.**
   - PC가 촬영한 뒤 기본값 OK, δ=0으로 보낸다.
   - '다음 웨이퍼 NG' 버튼으로 수동 지정한다. SIM과 LIVE 모두에서 된다.
6. **대기 자세 θ120, UV 받침 높이 z183, ToF 있음 문턱 120 mm, Sharp 검증 허용 ±3 mm, 판정 응답 제한 5 s**는 모두 ASSUMED로 둔다.

### 구조
- **`source.py`**: SIM(`CellSim`)과 LIVE(`LiveSource`)가 같은 메서드를 낸다.

  - Mega가 `CAP`(촬영 요청)를 보내면 → 카메라로 캡처하고 → 판정한 뒤 → `JDG`로 답한다.
  - 시뮬도 같은 경로(외부 판정 모드)를 쓴다.
- **`texts.py`**: 알람·이벤트 한글 문구와 headline을 모은다. SIM과 LIVE가 같은 글을 보이게 한다.
- **`protocol.py`(순수) + `PROTOCOL.md`(펌웨어 작성자용 규격)**
  - 줄 형식: `$TYPE,k=v,...*HH`. HH는 XOR 체크섬, ASCII만 쓴다.
  - 길이: PC→Mega ≤ 60 B(Mega 수신 버퍼 64 B), Mega→PC ≤ 200 B.
  - Mega→PC 메시지
    - `HEL`: proto, boot id
    - `ST` 20 Hz: 상태, 단계, θ/Z/R 지령값, θ 센서 마스크, Z/R Sharp mm, S4, E-STOP, D9, UV, A_UV, KSD
    - `SL` 변경 시: ① 슬롯 코드 `U/O/K/N/E`, ③ 포인터, 대차 받침 `F/W/D/-`, 포크, 카운터
    - `EV`: 이벤트·알람
    - `CAP`: 촬영 요청
    - `ACK`: 명령 응답
  - PC→Mega 메시지
    - `HB` 0.5 s
    - `CMD`: id, 명령, 기대 상태
    - `JDG`: 판정 결과
  - 규칙
    - 하트비트가 1.5 s 끊기면 Mega는 현재 축 동작만 끝내고 PAUSED(LINK)가 되며 UV를 끈다.
    - 판정 응답이 5 s 안에 없으면 JUDGE_TIMEOUT.
    - δ가 허용 창 밖이면 CORR_RANGE.
    - Mega는 최근 명령 id 8개를 기억해 같은 명령을 두 번 실행하지 않는다.
    - Mega는 포트를 열 때 리셋되므로 → 부팅하면 IDLE·원점 미확정·UV 꺼짐 상태로 시작하고, 스스로 움직이지 않는다.
    - 단계 키는 `sequence.step_catalog()`와 같아야 한다.

  - 전송 방식: `SerialTransport`(pyserial은 필요할 때 import, 1 s마다 재연결), `TcpTransport`, `FakeTransport`, 테스트용 `QueueTransport`

  - 하드웨어 없이 LIVE 전체를 시험하는 데 쓴다.

사용자가 각 카세트 도크 하단에 VL53L0X를 달아 웨이퍼 개수를 확인하기로 했다. 현재 R9 모니터는 "투입 5장 가정 + S4 확인"으로 동작한다.
하단 TOF는 **가장 아래 웨이퍼까지의 거리 하나**만 준다. 그래서 개수는 "위로 빈칸 없이 붙어 있다"는 가정 아래의 추정이다.

핵심 이점은 따로 있다. 투입은 아래 슬롯부터 꺼내므로, 꺼낼 때마다 TOF가 **바로 다음에 꺼낼 웨이퍼**를 본다. 따라서 중간 빈칸이 있어도 S4 알람 없이 건너뛸 수 있다.
OK/NG는 위 슬롯부터 채우므로 같은 공식(개수 = 5 − 가장 아래 슬롯 + 1)이 그대로 맞는다.

### 기하 (가정 — 실물 치수 [불명])
| 항목 | 값 |
|---|---|
| 센서 높이 `TOF_Z` | 140 (카세트 바닥판 z172~180 아래 30 mm 이상. VL53L0X 최소 거리 약 30 mm) |
| 거리 | d = Sn − TOF_Z → 슬롯 1~5 = 50 / 68 / 86 / 104 / 122 |
| 빈 카세트 | 윗레일 밑면 `CASS_TOP_Z` 284 → d = 144 |
| 카세트 없음 | 범위 밖(VL53L0X 코드 8190) |
| 판정 허용 `TOF_TOL` | ±6 (슬롯 간격 18의 절반 9보다 작게), 시뮬 잡음 ±1.5 (시드 고정) |

### R축 리밋 스위치 (사용자 확인: 리니어 모터 양 끝단에 리밋 스위치 있음)
- 시뮬 동작은 바꾸지 않는다. 후진 끝 리밋을 S3(후진 확인)로 쓴다는 것을 README와 `cell_config` 주석에 명시한다.
- README '현장 확인'에 두 가지를 추가한다.
  1. 리밋 스위치가 **MCU가 읽을 수 있는 신호선으로 나오는지** 확인해야 한다. 내장형은 모터 전원만 끊고 신호를 내보내지 않는 경우가 많다. 그러면 S3로 쓸 수 없으니 신호선 배선이나 외부 스위치가 필요하다.
  2. 전진 끝 리밋은 풀 스트로크(실측 62) 위치라서 공정값 R51과 R85를 확인하지 못한다. 기구 스토퍼로 스트로크를 51에 맞추면 전진 리밋이 'R51 도달 확인'을 겸한다. R85는 실린더 2개 각각의 끝단 리밋으로 확인한다. 둘 다 [불명]이다.
- θ와 Z 원점 방식(수동 정렬 또는 S1·S2 센서)은 사용자가 아직 정하지 않았다. 그래서 시뮬은 현재 센서 원점을 유지한다.
- **R 구동 = L298 (사용자 결정)**: README '2단계 착수 조건'과 '현장 확인'에 다음을 적는다. 시뮬 동작은 바꾸지 않는다.
  - L298은 정방향·역방향과 PWM만 할 수 있고 위치를 모른다. 정확히 아는 위치는 끝단 리밋뿐이고, 중간 위치를 시간으로 멈추면 부하와 전압에 따라 흔들린다. 그래서 R51은 기구 스토퍼로 스트로크를 맞추는 방식을 권장한다.
  - 실린더 2개(R85)는 L298의 A·B 채널에 하나씩 연결한다.
  - 끝단 도달은 리밋 신호선으로 확인하거나, 신호선이 없으면 L298 SENSE 저항으로 전류가 0으로 떨어지는 것을 보고 판정한다.
  - 정지는 브레이크(IN1=IN2)로 하고, 시간 초과 알람을 둔다(S3가 2초 안에 안 들어오면 알람, 시뮬에 이미 있음).
  - 전압 강하 2~4 V를 고려해 액추에이터 정격 전류와 L298 채널 정격 2 A를 비교한다. 방열판과 플라이백 다이오드가 필요하다(모듈형은 내장). 실측값은 [불명]이다.

### Context
사용자는 이 화면을 다른 사람들 앞에 띄우고 **직접 설명한다**. 회색 부제를 한 번 지웠는데도 "글씨가 많고 전체적으로 난잡하다"는 피드백이 다시 왔다.

읽기 전용 디자인 검토를 돌렸다. 구성은 텍스트 목록 정리 1명, 설계안 3개, 심사 3명, 종합 1명이다. 결과는 다음과 같다.
- 화면 글자가 약 150개다(목록 92종).
- 같은 정보가 18곳에서 중복 표시된다. 예를 들어 WAIT_S5 상태는 5곳에 나온다.
- 주황색이 '지금 진행 중'과 '주의' 두 뜻으로 같이 쓰인다.
- 상자가 과밀하다.

사용자 결정은 4개다.
- 발표용 기본 화면에 **'상세' 토글**을 둔다.
- 단계 설명 문구는 넣지 않는다.
- 사이클 시간은 '상세'에서만 보인다.
- 카메라 칸은 작게 유지한다.

범위는 `wafer_cell/web/{index.html,app.js,style.css}`와 README다. `sim.py`, `sequence.py`, `server.py`는 건드리지 않는다.

4. **S4는 빈 슬롯과 픽업 실패를 구분하지 못한다.** → 확정된 정책대로 알람을 띄우고 운전자가 확인한다. 3D 프린트 웨이퍼는 **밝은색 필라멘트를 권장**한다(검은색은 IR을 흡수해 S4와 TOF가 불안정).
5. **모형 웨이퍼 여유가 빠듯하다.** 삽입 틈 0.5mm, 리프트 후 윗 선반까지 (3.5−t)mm, 슬롯 10에서 상단 레일까지 (3.5−t)mm, 크래들 재픽업 후 패드까지 0.5mm다. FDM 휨이 이보다 크면 부딪힌다. → t를 설정값으로 두고 인터록 패널에 여유(mm)를 표시한다. 문서 H②E(틈 중앙화)를 검토하라고 권고한다(기구 사안).
6. **원점 순서**: 문서의 θ1 → Z 순서는 공정 중 정전 뒤 Z가 스테이션 높이(ZC 180 이상)에 있으면 선회하다 충돌한다. 수축한 블레이드 끝 R203도 스테이션 웨이퍼와 17.5mm 겹친다. → 위 확정 절차로 해결했다.
7. **R 스트로크 62 vs 공정 51**: 51에서 멈추는 스토퍼나 리밋이 필요하다(문서는 실린더 추력을 30N으로 제한하라고 권고). 이 리밋 스위치를 **R 전진 확인 입력으로 겸용하기를 권장**한다(약점 1의 R 부분이 해결된다).
8. **단계 10에 S3 확인이 없다**(문서 표). 단계 11에서 전진한 채 하강하면 백라이트 박스와 부딪힌다. → 시퀀스에 Expect(S3)를 추가한다. 90°와 180°에서는 RX 변경을 ZC 181, 187, 192에서만 허용한다.
9. **검사 크래들(90°)에는 센서가 없다.** 비정상 정지 뒤 재시작하면 단계 7에서 충돌할 수 있다. → 웨이퍼 위치를 정지와 원점 복귀 뒤에도 유지한다. 새로 시작할 때는 C90 비어 있음을 운전자가 확인하고(카메라 화면 참고), C180은 S5로 확인한다.
10. **웹 버튼은 안전장치가 아니다.** → 조작부에 `소프트 정지 — E-STOP 아님`이라고 표시한다. 하드웨어 E-STOP 배선이 2단계 조작 기능의 전제조건이다.
11. **`아두이노_핀맵.cell`(한셀)은 읽을 수 없다.** → 2단계 착수 시 xlsx/CSV로 받는다.

### 시퀀스와 인터록 (`sequence.py`, `geometry.py`)
- **동작 종류**: `MoveZ`, `MoveR`, `Rotate(목표, 경유)`, `Expect(센서, 값, 제한시간 2s)`, `Capture`, `WaitUntil(S5 비움)`, `OperatorConfirm`.
- **원점 절차**: R0 & Expect S3 → Z↓ & S2(ZC 95) → ZC 105 → θ 0 & S1 → ZC 95. 제한시간은 20s다.
- **장당 21단계**: 문서 표를 그대로 옮기되 다음을 보강한다.
  - 단계 10에 S3 확인
  - 단계 12는 ZC 181 → RX 51 순서
  - 단계 21은 ZC 105 → θ 180→90→0 & S1
- **N보다 위 슬롯**은 TOF상 비어 있으므로 건너뛴다. 슬롯 ≤ N에서 S4가 없으면 `ALARM(S4 없음: 빈 슬롯 또는 픽업 실패)`을 띄우고 운전자 선택을 기다린다.
- **선회 허용 조건**: ZC = 105 ∧ RX = 0 ∧ S3. 원점 절차의 θ 원점 복귀도 같은 규칙을 따른다(예외 없음).
- **충돌 판정** (`geometry.py`, 발생 시 `COLLISION` 알람):
  - θ=0에서 블레이드 면이나 운반 웨이퍼 띠가 대상이 아닌 점유 슬롯의 [Sk−4, Sk+t]를 지나감(RX 0 포함)
  - 운반 웨이퍼 윗면 ≥ S(n+1)−4, 또는 ≥ 306
  - 90°·180°에서 RX 0이고 크래들이 점유된 상태로 z252를 통과
  - 블레이드 끝 ≥ R262에서 ZC 181 이하로 하강(허브)
  - 선회 중 운반 웨이퍼 윗면 ≥ 180
- **S4 기하 판정**: 회전된 S4 점 위에 웨이퍼가 있고, 그 하면이 ZC+64에서 0~5mm 위에 있을 때 ON이다. 2단계 시리얼 소스도 같은 의미로 쓴다.

### 시뮬레이터 (`sim.py`)
- **등속 이동**이다. 가속을 무시하므로 사이클 추정은 하한값이다. 가정값으로 장당 82.5초(슬롯 1)에서 104.1초(슬롯 10), 10장에 약 15.6분이다.
- **웨이퍼 이동**: 높이 교차로 판정한다(검증 완료. 슬롯 1·10, 두 크래들에서 픽업 3/안착 9/재픽업 13/안착 19만 발생). 충돌 판정이 먼저 걸리면 이동하지 않는다.
- **상태**: `IDLE, HOMING, READY, RUNNING, WAIT_S5, WAIT_OPERATOR, PAUSED, ALARM, ESTOP, CASSETTE_DONE`. 축마다 `homed` 플래그가 있고, ESTOP이 걸리면 homed=false가 되어 원점 복귀만 허용한다.
- **명령**: `home, cassette_ready, start, pause, resume, stop, reset(알람 해제만, 동작 없음), confirm(empty|retry|c90_clear), speed, load_map, fault(...), debug_hold(step)`. 뒤의 네 가지는 SIM 전용이다.
- **고장주입**: 빈 슬롯(투입 맵), S4 오감지(거짓 없음/있음), 다음 로봇 지연, S3 미확인, E-STOP, 카메라 끊김, 시뮬 내부 예외.
- **알람 9종**: 원점 타임아웃, 선회 전 S3 미확인, S4 없음(확인 대기), 안착 후 S4 잔존, S5 점유 지속(60s 경고), E-STOP, 카메라 실패, 0° 복귀 시 S1 불일치(벨트 이빨 튐), COLLISION.
- **웨이퍼 기록**: 웨이퍼별로 위치(slot/blade/C90/C180/handed_off), 시각, 사이클, 캡처 파일을 남기고 CSV에 한 줄씩 추가한다.

### 웨이퍼 수 (`tof.py`)
- 계산 순서:
  1. d > d_empty − tol이면 `EMPTY`
  2. |d − d1| < 12 − tol이고 빈 카세트와 구분이 안 되면 `0 또는 1`
  3. 그 외에는 n = round((d1 − d)/12) + 1이고, 잔차가 tol(±4mm)을 넘으면 `INVALID`
- 보정값이 없을 때는 문서 기하로 계산한 기본값을 쓴다. TOF 높이 z360과 t=2는 `가정`으로 표시한다.
- 시뮬레이터는 빔 아래 바닥 면(기본 z180 베이스판)을 모델링한다. 그래서 모호한 경우가 테스트에 실제로 드러난다.
- 화면 표시: `투입 추정 N`(준비 버튼 시점) / `S4 확정` / `남은 수`, 그리고 불일치 경고.

### 서버 (`server.py`)
- **실행**: `py -3.13 wafer_cell/server.py [--cam 1|none] [--port 8765] [--lan] [--speed 1]`. 콘솔에는 `http://127.0.0.1:8765/`를 출력한다(localhost는 ::1로 해석될 수 있어서).
- **엔드포인트**:
  - `/events`: SSE. 첫 메시지 `retry: 1000`, 20Hz 간결 스냅샷
  - `/api/state`: 상태 1회 조회
  - `/camera.jpg?seq=`: 공유 JPEG 1장. 클라이언트는 `cam_seq`가 바뀔 때만 요청하므로, 탭당 긴 연결은 SSE 하나다
  - `/captures/<^[A-Za-z0-9_.-]+\.jpg$>`
  - `POST /api/cmd`
- **스냅샷 필드**: `tick, t, boot_id, source(SIM|LIVE), state, step, 축(0.1 반올림), homed, 센서, 슬롯, 웨이퍼 위치, cam_seq, log_seq`. 로그와 웨이퍼 기록은 seq 기반 증분으로 보낸다. `json.dumps(allow_nan=False, separators=...)`.
- **조작 보호**:
  - 클라이언트 IP가 loopback(`ipaddress.is_loopback`)이어야 한다
  - `Content-Type: application/json`이어야 한다
  - Host와 Origin이 `127.0.0.1:포트` 또는 `localhost:포트`여야 한다
  - 기동 시 무작위 토큰을 loopback 페이지에만 주입하고 POST에서 검사한다
  - `{cmd, expect_state}`가 현재 상태와 맞지 않으면 409
  - SIM 전용 명령은 LIVE에서 거부한다
  - 원격 페이지는 `view_only`를 받아 조작부를 숨긴다
- **견고성**:
  - 시뮬 스레드의 tick을 try/except로 감싼다. 예외는 ALARM(시뮬 내부 오류)로 바꾼다.
  - 스트림 루프는 `ConnectionError`와 `OSError`가 나면 조용히 종료한다. `handle_error`에서도 연결 오류는 조용히 넘긴다.
  - 전역 `stop_event`, `daemon_threads=True`, `disable_nagle_algorithm=True`를 쓰고, 이벤트는 한 번의 write로 보낸다.
  - Windows에서는 `allow_reuse_address=False`로 해서 이중 실행 시 'address in use'로 종료한다.
  - MIME 맵을 명시하고(.js는 text/javascript) `Cache-Control: no-cache`를 붙인다. 상태줄과 헤더는 ASCII만 쓴다.
  - **콘솔 출력은 메인·로거 스레드에서만 한다**(QuickEdit 멈춤 방지, ASCII 전용).

### 화면 (1920×1080 기준, 1536×864에서도 잘리지 않게; CELL_V9 색 토큰; 다크 기본 + 라이트)
- **상단 바**:
  - `웨이퍼 이송셀 CELL_V9 · 공정 모니터`
  - 상시 배너 `시뮬레이션 — 실제 장비 아님`
  - 운전 상태, 슬롯 n/N, 처리 수, 사이클(가정 속도 기준), 시계, 시연 모드와 테마 토글
- **공정 흐름 띠**(처음 보는 사람용): `카세트 취출 → 검사 촬영 → 반출 → 인계`. 현재 단계를 크게 강조하고 **"지금 하는 일"과 "왜"**(문서 문장 기반)를 한 줄씩 붙인다.
- **3열 구성**:
  - **평면도(약 760px)**: 문서 SVG 좌표를 쓰고 (x, −y) 변환은 한 곳에서만 한다. 그룹은 세 가지로 나눈다.
    - 고정: 페데스탈, 스테이션, S1, S5, CAM
    - 회전(`rotate(−θ)`): 디스크, 캐리지, 실린더, S2, S3
    - 이동(`translate(RX)`): 블레이드, S4, 운반 웨이퍼
    - 선회원 R203/R234.5와 센서 LED도 그린다.
  - **입면도(약 440px)**: 블레이드 방위를 따라 자른 r–z 단면이고, 블레이드는 항상 오른쪽을 향한다. z 범위는 고정이다.
    - |θ−θs| ≤ 2°일 때만 그 스테이션(카세트 10슬롯 슬롯맵 / 검사 크래들+백라이트[z 불명]+카메라 / 반출 크래들)을 그린다.
    - 선회 중에는 선회 대역 z158~174와 목적지 스테이션을 반투명으로 보여주고 `선회 중 0°→90°`라고 표시한다.
    - 블레이드 끝은 4배 확대 인셋으로 보여준다.
  - **우측(약 640px)**:
    - 카메라 640×360: 라이브면 STALE/NO SIGNAL 배지, SIM이면 브라우저가 그린 **개념도**(백라이트 띠 + 웨이퍼 외곽 + 포크 끝 그림자)
    - 최근 캡처 썸네일
    - 웨이퍼 수 한 줄(추정/확정/남은 수)
    - 축(지령/목표)
    - 센서 칩 한 줄(S1~S5, E-STOP, 기대값 대비 실제값)
    - 인터록(선회 허용/금지 사유, 여유 mm)
- **하단**: 타임라인(원점 · ①1–5 · 6 · ②7–15 · 16 · ③17–21 · 인계)과 진행 바. 이벤트 로그와 알람은 접이식 서랍으로 둔다.
- **조작부**:
  - 원점복귀, 카세트 준비, 시작, 일시정지/재개, `소프트 정지 — E-STOP 아님`, 배속, 투입 맵, 고장주입
  - 모든 동작 명령에는 현재 단계와 인터록 상태를 보여주는 확인 모달을 띄운다(비차단)
  - 연결이 끊기거나 데이터가 멈추면 전부 비활성화한다
- **시연 모드**: 로그, 세부 수치, 조작부를 숨긴다. 평면도, 공정 흐름 띠, "지금 하는 일/왜"를 크게 보여준다.
- **애니메이션**: 서버 시간 `t` 기준으로 스냅샷 최대 4개를 버퍼링해 보간한다. θ는 unwrap해서 보간하고, 이산값(웨이퍼 위치, 상태)은 즉시 전환한다.
- **감시**: 1초 넘게 메시지가 없거나 `tick`이 멈추면(PAUSED 제외) `데이터 정지` 오버레이를 띄우고 조작을 막는다. `boot_id`가 바뀌면 클라이언트 상태를 초기화한다. EventSource가 CLOSED가 되면 백오프 후 다시 만든다.
- UI 구현 시 `frontend-design` 스킬로 디자인 패스를 한다.

## 구현 순서
1. `cell_config` → `sequence` → `geometry` → `tof`와 각 테스트(인터록: ZC≠105에서는 선회 없음, 슬롯 역순은 COLLISION, RX 62 설정은 허브 COLLISION, TOF d=170/180/201 경계)
2. `sim`과 테스트(10장 전체, dt 0.02와 0.2의 사이클 차이 0.1s 이내, 빈 슬롯은 WAIT_OPERATOR, S5 지연은 WAIT, ESTOP → home → 재시작 시 C90 확인 요구, 예외 → ALARM)
3. `camera_feed` → `server`와 테스트(`('127.0.0.1', 0)` 임시 포트, cam 비활성, `/api/state`, SSE 첫 이벤트는 `http.client` timeout 2s, 토큰/Origin/Content-Type 거부, 20s 워치독, try/finally 종료)

5. README, CLAUDE.md 갱신(웨이퍼셀 절 추가, 테스트 수 14→19와 목록, `ddd/` 경로 표기 정정, wafer_cell은 §1/§6 재활용 로봇 규칙의 예외임을 명시)

## 2단계(실연동) 착수 조건 — 이번 범위 아님
- 제어보드를 선정한다. 시퀀스와 인터록은 **MCU에서 실행**하고, PC는 START/PAUSE/HOME/STOP만 보내고 상태를 받는다.
- **PC→MCU 하트비트**(0.5s)를 둔다. 1.5s 동안 끊기면 MCU가 다음 안전 지점(ZC 105, RX 0)에서 멈춘다. 상태 JSON에 `link_ok`를 넣는다.
- 촬영 요청/응답 핸드셰이크(타임아웃 시 CAM 알람)와 백라이트 제어 주체를 정한다.
- 입력은 S1~S5, E-STOP, AL×2, **R 전진 리밋(51)**으로 8개 이상의 디지털 입력이 필요하고, TOF용 I2C도 필요하다. 출력은 STEP/DIR/EN×2, 실린더 정·역, 백라이트다.
- Z 10mm/s(스텝 5000/s)가 AccelStepper로 가능한지 확인한다[불명]. 슬립링이냐 케이블 루프냐(θ 원점 탐색 범위 ±190°)를 정한다.
- COM 포트는 COM3/COM8과 달라야 한다(`cell_config`에서 `common.config`와 비교해 검증). 핀맵은 xlsx/CSV로 받는다.

## 검증
- **순수 로직 테스트**(하드웨어 불필요): 새 테스트 5개 + 기존 14개, `Get-ChildItem tests\test_*.py | % { py -3.13 $_.FullName }`.
- **컴파일/임포트**: `py -3.13 -m compileall -q wafer_cell`, `py -3.13 -c "import sys; sys.path.insert(0,'.'); import wafer_cell.server"`.
- **클라우드 세션 검증**(Python 3.11):
  - 새 테스트 5개를 실행한다(numpy와 cv2가 필요 없음).
  - 기존 테스트는 `pip install numpy pyserial` 뒤 가능한 것만 돌리고, 결과를 정직하게 보고한다.
  - 서버를 `--cam none`으로 띄우고 Node Playwright(`NODE_PATH=/opt/node22/lib/node_modules`)로 스크린샷을 찍는다. 크기는 1920×1080과 1536×864, 상태는 `debug_hold`로 고정한 IDLE, 단계 6 선회, 단계 11 촬영, WAIT_S5, WAIT_OPERATOR, COLLISION, 시연 모드다.
  - 콘솔 에러 0을 확인하고, 스크린샷은 사용자에게 보낸다.
- **사용자 현장 확인**(하드웨어 의존, 단정하지 않음):
  - 웹캠: `--cam 1`에서 라이브 영상이 나와야 하고, USB를 뽑으면 1초 안에 STALE이 떠야 한다.
  - 이중 실행: 두 번째 서버는 'address in use'로 종료돼야 한다.
  - TOF(2단계): 빈 카세트와 슬롯 1~10 거리를 기록한다. 인접 차이 12±2mm, 반복 편차 ±3mm, |d_empty − d1| ≥ 8mm이면 합격이다. 빔 축은 y=0±5mm, x 225~240에 둔다.
- **커밋/푸시**는 CLAUDE.md §8에 따라 사용자가 요청할 때만 브랜치 `claude/gracious-cannon-lh630u`에 한다(컨테이너가 휘발성이므로 완료 시 요청 권장).
