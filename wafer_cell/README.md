# 웨이퍼 검사셀 R9 공정 모니터 (`wafer_cell/`)

R9 셀의 공정을 브라우저에서 **실시간 애니메이션과 상태 대시보드**로 보여준다.
셀은 카세트 3개(① 투입 · ③ NG · ④ OK), ② 검사 크래들, OK 카세트를 실어 가는 대차, 3축(θ1 · Z · R)으로 이루어진다.
**1단계 = 시뮬레이션**이다. 실장비 연동은 2단계에서 한다.

- 공정 흐름 출처: 비디오 `R9 웨이퍼 검사 셀`(88 s, 2026-10-12 제공)
  - 자막에 나온 수치는 그대로 쓴다.
  - 비디오에 없는 값은 `cell_config.ASSUMED`(가정)로 둔다.
- 새 의존성 없음: 표준 라이브러리 HTTP 서버를 쓴다. 카메라를 쓸 때만 기존 opencv가 필요하다. 인터넷(CDN)은 필요 없다.

## 실행 (작업폴더 = 저장소 루트, Windows PowerShell)

```powershell
py -3.13 wafer_cell/server.py                  # SIM, 카메라 없음(개념도)
py -3.13 wafer_cell/server.py --cam 1          # 검사 웹캠 인덱스 1 (tests/find_camera.py 로 확인)
py -3.13 wafer_cell/server.py --speed 5        # 5배속
py -3.13 wafer_cell/server.py --lan            # 같은 네트워크에 공개(원격 = 보기 전용)
```
- 브라우저 주소는 **`http://127.0.0.1:8765/`**이다(localhost는 ::1로 풀려 느릴 수 있음). F11로 전체화면.
- `--lan`이면 Windows 방화벽 허용 창이 뜬다. 개인 네트워크만 허용한다. 이 PC에서도 조작하려면 127.0.0.1로 접속한다.
- 코드를 갱신(`git pull`)한 뒤에는 서버를 재시작하고 브라우저에서 **Ctrl+F5**를 누른다.

**사용 순서**: **원점 복귀 → 시작**. 그 뒤로는 웨이퍼가 투입 카세트에서 OK/NG 카세트로 계속 흘러간다.
- 헤더에는 지금 누를 수 있는 버튼만 나오고, 다음 동작 버튼이 강조된다.
- `도구 ▾`에 다음이 들어 있다.
  - 시뮬 전용: 배속, `다음 웨이퍼 NG`, `작업자 자동`, 투입 맵, 고장 주입, E-STOP 시뮬
  - 공통: 테마, 이벤트 로그

## 공정 (비디오 흐름)

**스테이션** (위에서 볼 때 시계방향)

| θ1 | 스테이션 | 비고 |
|---|---|---|
| 180° | ① 투입 카세트 | 5장 |
| 120° | ② 검사 크래들 | 백라이트 C-03N 위 크래들 C-02N, StreamCam이 위에서 촬영 |
| 60° | ③ NG 카세트 | |
| 0° | ④ OK 카세트 | 클램프 윗판 C-08K1S |
| −90° | 대차 받침 자리 | R85 |

- **대기 자세**: θ120 · Z105 · R0
- **선회 규칙**: 선회는 늘 Z105 · R0 · S3에서만 한다. 예외는 대차 적재의 T3(Z228.5)와 T8(Z241)뿐이다.

**원점**

R 수축(S3) → Z 최하단(S2) → Z105 → θ 원점(S1, 0°) → 대기 120°

**웨이퍼 한 장** (슬롯 높이 Sn = 190 + 18(n−1), n = 1..5)

| 단계 | 동작 |
|---|---|
| 1 | 투입 180°로 선회 |
| 2 | Z = Sn−68.5 → R51 |
| 3 | +7.5 들기(받침 이빨에서 4.5 뜨고 앞 턱 2.5를 넘음) → S4 확인 → R0 → Z105 |
| 4 | 검사 120°로 선회 |
| 5 | Z192 → R51 → Z183(패드 252에 내려놓음, S4 꺼짐) → R0 |
| 6 | 포크를 뺀 채 촬영하고 판정(OK/NG) |
| 7 | R51 → Z192(다시 들기, S4) → R0 → Z105 |
| 8 | OK 0° 또는 NG 60°로 선회. OK는 NG 위치를 지나가며, 도착하면 S1을 확인한다 |
| 9 | Z = Sk−61 → R51 → Z = Sk−68.5(내려놓음) → R0 → Z105 |
| 10 | 대기 120°로 복귀 |

- **투입은 아래 슬롯부터**(1→5) 꺼내고, **OK/NG는 위 슬롯부터**(5→1) 채운다.
  - 이유: 포크를 수축한 상태에서도 스테이션 웨이퍼와 겹친다. 그래서 R0으로 오르내릴 때는 빈 슬롯만 지나가야 한다.
  - 이 순서를 어기면 `geometry.z_move`가 COLLISION으로 막는다.

**작업자 일** (`작업자 자동` ON이면 8 s 뒤 자동 처리, OFF이면 헤더 버튼으로 처리)

| 상황 | 버튼 | 셀의 동작 |
|---|---|---|
| 투입 카세트가 빔 | `투입 카세트 교체` (5장) | `WAIT_INPUT`에서 대기 |
| OK 카세트를 대차로 보낸 뒤 OK 도크가 빔 | `빈 OK 카세트 놓음` | `WAIT_OK`에서 대기 |
| NG 카세트가 가득 참 | `빈 NG 카세트 놓음` | `WAIT_NG`에서 **멈추고 교체를 요청** |

**대차** (OK 카세트가 가득 차면 호출. 메카넘 AGV, 받침 4칸)

- **호출과 도킹**: 대차가 도착해 PL 도킹(태그 ID 1)하면 '앞 왼' 받침이 로봇 앞에 온다.
- **적재 단계**

  | 단계 | 동작 |
  |---|---|
  | T1 | θ120 → −40 (클램프 윗판을 피해 비켜서 오름) |
  | T2 | Z228.5 |
  | T3 | θ −40 → 0 (Z228.5에서 선회) |
  | T4 | R51 (윗판 밑으로) |
  | T5 | Z241 (카세트 + 웨이퍼 5장을 듦) |
  | T7 | R0 |
  | T8 | θ0 → −90 (Z241에서 선회) |
  | T9 | R85 |
  | T10 | Z205 (받침에 내려놓음) |
  | T11 | R0 |
  | T12 | Z105 |
  | T13 | θ120 |

  비디오에 T6은 없다.
- **다음 받침으로 옮기기**
  - 앞 오른: 물러남 −120 → 옆걸음 −200 → 도킹
  - 뒤 왼: 물러남 → 옆걸음 +200 → 제자리 180° 회전(뒤 카메라 CM-02) → 도킹
  - 뒤 오른: 물러남 → 옆걸음 −200 → 도킹
- **출발**: 카세트 4개를 실으면 대차가 떠난다. 비디오 마지막 화면은 검사 21장이었고, 시뮬도 같은 수가 나온다.

## 화면 구성
기본 화면은 발표용이다(설명은 발표자가 한다). 글자는 상태와 이름만 둔다.
- **헤더**: 제목, `시뮬레이션` 배지(실장비면 초록 `실장비`), 상태 단어, 버튼, `도구 ▾`, `상세`. 소프트 정지는 항상 같은 자리에 있다.
- **흐름 띠**: 투입 › 검사 › NG › OK › 대차
  - 그 아래 큰 제목 한 줄이 붙는다. 예: `웨이퍼 3 — ② 검사 크래들에 놓기`, `대차 1 번째 — T8 든 채 선회 θ 0 -> -90`
  - 그 아래 글자 없는 진행 막대가 있다.
- **평면도**(위에서 본 셀): 스테이션 4곳과 대차를 그린다. 대차는 받침 4칸, 실린 카세트, 이동/회전 애니메이션을 보여준다.
- **입면도**: 포크 방향 단면이다. 서 있는 스테이션의 카세트/크래들/대차 받침과, 포크 위 웨이퍼 또는 카세트를 그린다.
- **하단**
  - 검사 카메라: 개념도 / 실카메라 LIVE·영상 정지·신호 없음. 판정 OK/NG 배지가 붙는다.
  - `검사` 누적 수
  - 투입·NG·OK 카세트 5칸(색으로 상태 구분)
  - 대차 받침 4칸
- **알람 바**: 알람, 운전자 확인일 때만 나온다. 알람이 센서를 지목하면 평면도 LED에 빨간 링이 생긴다.

**상세** (`상세` 버튼 또는 D 키, `?detail=1|0`, 마지막 선택을 기억한다. 시뮬은 기본 OFF, 실장비는 기본 ON)
- 제목 옆에 수치 한 줄(Z·R 목표값)이 붙고, 진행 막대에 단계 번호가 붙는다.
- 카세트 수(투입 · OK · NG · 대차), 누적(OK · NG · 대차 출발), 사이클(가정 속도)을 보여준다.
- `축 (지령값)` θ1 / Z / R, 센서 S1~S4·E-STOP, 선회 허용/금지(사유는 툴팁)를 보여준다.

## 정직성 표기 (화면이 거짓 확신을 주지 않게)
| 표시 | 의미 |
|---|---|
| `시뮬레이션` 배지 | 항상 표시. 데이터 소스가 시뮬레이터라는 뜻이다(툴팁: 실제 장비 아님 · 사이클은 가정 속도) |
| `축 (지령값)` (상세) | 스테퍼는 보낸 스텝으로 계산한 값이다. 엔코더를 읽지 않는다. R은 후진(S3)만 센서가 있다 |
| `사이클 (가정 속도)` (상세) | 가정 속도에 등속(가속 무시)을 적용한 하한값이다. 그래서 기본 화면에서 뺐다 |
| 대차 움직임 | 시간 모델이다(아래 가정값). 실제 AGV 상태를 받지 않는다 |
| `데이터 정지` 오버레이 | SSE가 1.5 s 무응답이거나 tick이 멈추면 뜬다. 이때 조작 버튼은 비활성이다 |

## 상태 스냅샷 (SSE `/events`, `/api/state`) — 2단계 시리얼 소스도 같은 필드로 맞출 것
`tick, t, source, state, speed, pose{theta,zc,rx}, target, homed, step{key,group,title,detail,stage,action,actions}, program,
phase, stage, headline, subline, slot, sensors{S1..S4,ESTOP}, expect, docks{input|ng|ok:{present,count,slots[{n,status,no}]}},
fork{wafer,judgment,cassette}, inspect{wafer,judgment}, cart{state,seats,rot,lat,dist,aligned,caption,loaded,departed,camera},
operator{auto,pending[]}, judgment, ng_next, ng_rate, occ, wafers, alarm, prompt, interlock, counts, faults, insp_verified, captures, log_seq`

**상태**: `IDLE, HOMING, READY, RUNNING, WAIT_INPUT, WAIT_OK, WAIT_NG, WAIT_CART, WAIT_OPERATOR, PAUSED, ALARM, ESTOP`

**명령**: `POST /api/cmd {cmd, args, expect_state}`
- 일반: `home, start, pause, resume, stop, reset, estop, confirm{choice: empty|retry|insp_clear}, operator{task: input|ok|ng}`
- SIM 전용: `speed, load_input, fault, remove_wafer, debug_hold, auto_operator, next_ng, ng_rate`
- 고장 주입: `s4_false_none, s4_false_present, s3_fail, belt_skip, camera_fail, cart_delay, sim_exception`

**보호**: 다음 조건을 모두 만족해야 명령을 받는다.
- loopback 클라이언트
- `Content-Type: application/json`
- Host/Origin이 127.0.0.1 또는 localhost
- 기동 토큰(`X-Wafer-Token`)

## 현장 확인 절차 (하드웨어 의존 — 코드로 단정하지 않음)
1. **R85 (대차 받침)**: 단일 실린더 실측 스트로크는 62다(2026-09-29). 비디오는 '실린더 2개 같이 밈'이다. 그래서 R85가 되는지는 **[불명]**이다.
   - 두 실린더를 이어 R0 → 85와 R51 정지를 각각 재본다.
   - R51 정지에는 스토퍼나 리밋이 필요하다.
2. **S4 (포크 IR 반사)**: 시뮬 판정 범위는 웨이퍼 하면 0~4 mm로 가정했다.
   - 포크 위 웨이퍼는 1.5 mm에서 켜져야 한다.
   - 슬롯에 내려놓은 뒤(4.5 mm)와 크래들에 내려놓은 뒤(5 mm)는 꺼져야 한다.
   - 여유가 0.5~1 mm뿐이다. 실제 센서의 감지 거리와 히스테리시스를 재서 `S4_RANGE`에 넣는다. 맞지 않으면 S4 위치나 각도를 바꿔야 한다.
3. **θ 범위 270°** (−90 ~ 180): 케이블/슬립링 경로가 −90 ~ 180을 견디는지 확인한다.
4. **웹캠**
   - `--cam 1`이면 라이브 영상과 LIVE 배지가 나온다.
   - USB를 뽑으면 **1초 안에** 영상 정지로 바뀌어야 한다.
   - 백라이트에서 노출이 포화되지 않는지 확인한다.
5. **이중 실행**: 서버를 하나 더 띄우면 `cannot start server on port 8765`로 종료되어야 한다.
6. **모형 웨이퍼**: 밝은색 필라멘트를 권장한다(검은색은 IR을 흡수해 S4가 불안정). 두께와 휨을 실측해 `WAFER_T`를 고친다.
   - 여유는 다음과 같다(mm): 삽입 틈 3.0, 들기 뒤 이빨 위 4.5, 위 받침까지 7.5, 크래들 5.5, 선회 7.5.

## 2단계(실장비) 착수 조건 — 미구현
- **제어보드 선정**: 시퀀스와 인터록은 MCU에서 실행한다.
- **하트비트**: PC→MCU 0.5 s 주기. 1.5 s 끊기면 안전 지점에서 정지한다.
- **촬영 요청/응답**을 정한다.
- **입력**: S1~S4, E-STOP, AL×2, R 전진 리밋(51)
- **대차(AGV) 통신**: 호출, 도착, 받침 정렬, 출발
- **배선**: 하드웨어 E-STOP
- **COM 포트**: COM3/COM8과 달라야 한다.
- **핀맵**: xlsx/CSV로 받는다.
