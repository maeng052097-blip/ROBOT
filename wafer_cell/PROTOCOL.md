# 셀 Mega ↔ PC 줄 프로토콜 (R22, 버전 1)

펌웨어(Arduino Mega 2560)를 작성하는 사람을 위한 규격입니다. 코드 구현은 `wafer_cell/protocol.py`(파서·검증), `wafer_cell/live.py`(PC 수신), `wafer_cell/fake_mega.py`(가짜 장비, 규격 예시)에 있습니다. `tests/test_wafer_protocol.py`가 이 문서와 코드가 같은지 검사합니다. 키를 하나라도 바꾸면 두 곳을 함께 고쳐야 테스트가 통과합니다.

## 0. 역할 — 누가 무엇을 결정하나

- **공정은 Mega가 결정합니다.** 시퀀스, 인터록, 센서 판정, UV 램프, 알람이 모두 Mega 책임입니다.
- PC는 세 가지만 합니다.
  1. 화면 표시
  2. 카메라 판정(`JDG`)
  3. 운전 명령 6개: `home` · `start` · `pause` · `resume` · `stop` · `reset`. 웹 버튼과 확인 창을 거쳐서만 보냅니다.
- PC가 축을 직접 움직이는 명령은 **없습니다.** 시뮬 전용 명령(고장 주입·배속 등)도 Mega로는 가지 않습니다.
- 웹의 '정지'는 소프트 정지일 뿐 E-STOP이 아닙니다. 하드웨어 E-STOP 사슬(D9)이 따로 있어야 합니다.
- **전원 투입 / 포트 열기:** Mega는 USB 포트가 열릴 때(DTR) 리셋됩니다. 리셋 뒤 상태는 다음과 같아야 합니다.
  - 부팅하면 **`IDLE` · 원점 미확정 · UV 꺼짐**으로 시작하고 스스로 움직이지 않습니다.
  - 부팅 직후 `HEL`을 한 번 보냅니다.

## 1. 줄 형식

```
$TYPE,key=value,key=value*HH\n
```

| 항목 | 규칙 |
|---|---|
| 시작 · 끝 | `$`로 시작하고 `*HH` 뒤에 `\n`이 옵니다. 수신 쪽은 `\r`을 버립니다. |
| 체크섬 `HH` | `$`와 `*` **사이** 모든 바이트를 XOR한 값을 16진수 대문자 2자리로 씁니다(NMEA와 같은 방식). 받을 때는 소문자도 허용합니다. |
| 문자 | ASCII 인쇄 문자(0x20–0x7E)만 씁니다. 값에는 `A-Z a-z 0-9 _ . + - / : #`만 쓰고 `$ * , =`와 공백은 쓰지 않습니다. |
| TYPE | 대문자 2~3자 |
| key | 영문 소문자로 시작하는 1~4자 |
| 값 | 숫자는 10진수입니다. bool은 `0`/`1`입니다. 값이 없으면 `-`를 씁니다. |
| 길이(`$`부터 `HH`까지, 줄바꿈 제외) | **PC → Mega ≤ 60 B**(Mega 수신 버퍼 64 B). **Mega → PC ≤ 200 B**. 넘는 줄은 버립니다. |
| 키 순서 | 상관없습니다. 모르는 키는 무시합니다(앞으로 확장할 수 있게). 같은 키가 두 번 나오면 오류입니다. |
| 전송 | 115200 bps, 8N1. TCP(`tcp:HOST:PORT`)로 보내도 같은 줄을 씁니다. |

수신 쪽 견고성은 `protocol.Decoder`가 기준입니다.
- 바이트가 쪼개져 와도 됩니다.
- `$` 앞의 쓰레기 바이트는 건너뜁니다.
- 한 줄에 `$`가 여러 개 있으면 마지막 `$`부터 읽습니다(앞은 끊긴 줄).
- 너무 긴 줄은 버리고 다음 `$`부터 다시 시작합니다.

오류 코드: `no_dollar` · `no_star` · `bad_hex` · `bad_crc` · `bad_char` · `too_long` · `bad_type` · `bad_field`

## 2. Mega → PC

### `HEL` — 부팅 인사 (부팅 직후 1회 + `CMD c=hello`를 받았을 때)

| 키 | 종류 | 뜻 |
|---|---|---|
| `p` | int | 프로토콜 버전. 지금은 **1**입니다. 다르면 PC가 '프로토콜 불일치'(VERSION)로 보고 명령을 막습니다. |
| `b` | word | 부팅 id(부팅마다 바뀌는 16진수 문자열). 이 값이 바뀌면 PC는 '장비 재시작'으로 봅니다. |
| `fw` | word | 펌웨어 이름/버전(선택) |

### `ST` — 상태 (20 Hz)

| 키 | 종류 | 뜻 |
|---|---|---|
| `q` | int | 순번 0–65535(넘치면 0부터). PC는 빠진 개수를 셉니다. |
| `ms` | int | Mega `millis()`. 값이 줄어들면 PC는 재시작으로 봅니다. |
| `st` | word | 상태(§4) |
| `stp` | word | 지금 단계 키(§5). 없으면 `-`. |
| `ai` | int | 단계 안 동작 번호(0부터, §5 표의 동작 순서). PC가 '무엇을 기다리는지'를 표시하는 데 씁니다. |
| `n` | int | 지금 ① 슬롯 1–5. 없으면 0. |
| `k` | int | 지금 ③ 넣을 슬롯 1–5. 없으면 0(선택). |
| `w` | int | 지금 웨이퍼 번호(집을 때 1부터 매김). 없으면 0(선택). |
| `th` | float | θ **지령값** deg. 범위는 [-45, 315)이고 0.01 단위입니다. |
| `zc` | float | Z 지령값 ZC mm(스텝 수로 환산) |
| `rx` | float | R 지령값 RX mm(실린더 시간 모형) |
| `hm` | int | 원점 확정 비트. 1 = θ, 2 = Z, 4 = R. 0–7입니다. |
| `ths` | mask5 | θ 자리 센서 5개. 순서는 TH0 · TH60 · TH120 · TH180 · TH270이고, `1` = LOW(그 자리에 있음)입니다. 예: `00100` |
| `zd` | float | Z Sharp 거리 mm(10–20번 평균). 읽을 수 없으면 `-`. ZC = 349.1 − zd. |
| `rd` | float | R Sharp 거리 mm. RX = rd − 104. |
| `s4` | bool | S4 포크 웨이퍼 |
| `ti` | bool | TOF-IN: ① 카세트 있음(문턱 판정 뒤 값) |
| `tn` | bool | TOF-NG: ③ 카세트 있음 |
| `d9` | bool | E-stop 사슬 살아 있음(D9 LOW = `1`). `0`이면 비상정지입니다. |
| `uv` | bool | UV 릴레이 켬 지령 |
| `au` | bool | A_UV 창 안(LED가 실제로 켜짐) |
| `ul` | float | UV 남은 초. 조사 중이 아니면 `-`(선택). |
| `pr` | word | 일시정지 이유 `USER` · `LINK` · `HOLD`. 아니면 `-`(선택). |
| `al` | word | 지금 알람 코드(§6). 없으면 `-`. |

### `SL` — 슬롯 · 카운터 (바뀔 때 + 1 s마다)

| 키 | 종류 | 뜻 |
|---|---|---|
| `in` | slots5 | ① 슬롯 1→5 코드: `U` 미처리(있다고 봄 — 슬롯마다 센서가 없음) · `O` 꺼냄(공정 중) · `K` 정상 원위치 · `N` 불량(③으로) · `E` 빈 슬롯(P3에서 S4 없음) · `-` 카세트 없음. 예: `KNOUU` |
| `ng` | int | ③ 현재 카세트에 넣은 개수 0–5. 다음 슬롯 = 5 − ng(위 슬롯부터). 카세트가 없으면 `-`. |
| `cs` | seats4 | 대차 받침 FL · FR · RL · RR 코드: `F` 처리 전 · `W` 셀에서 처리 중 · `D` 끝 · `-` 빈 받침 |
| `ca` | word | 대차 상태 `AWAY` · `MOVING` · `DOCKED` · `LEAVING` |
| `cal` | word | 로봇 앞에 정렬된 받침 `FL` · `FR` · `RL` · `RR` 또는 `-` |
| `cmv` | word | 대차 지금 동작 코드(선택): `CALL` · `ARRIVE:FL` · `RETREAT` · `LATERAL:-200` · `ROTATE` · `DOCK:FR` · `LEAVE` |
| `fw` | bool | 포크 위 웨이퍼(Mega가 아는 값) |
| `fc` | bool | 포크가 카세트를 듦 |
| `cr` | bool | ② 크래들 웨이퍼(센서가 없어 Mega 기억값) |
| `uh` | bool | UV 받침 웨이퍼(기억값) |
| `ins` | int | 판정 수 |
| `okc` | int | 정상 원위치 수 |
| `ngc` | int | 불량 수 |
| `emp` | int | 빈 슬롯 수 |
| `cyc` | float | 마지막 웨이퍼 사이클 s(선택) |
| `dep` | int | 떠난 대차 수 |
| `ju` | word | 마지막 판정 `OK` · `NG` · `ERR` · `-`(선택) |
| `jw` | int | 마지막 판정 웨이퍼 번호(선택) |
| `jdr` | float | 마지막 판정 δr(선택) |
| `jdt` | float | 마지막 판정 δθ(선택) |

### `EV` — 이벤트 · 알람 (생길 때)

| 키 | 종류 | 뜻 |
|---|---|---|
| `q` | int | 이벤트 순번 |
| `lv` | word | `I` 정보 · `W` 경고 · `A` 알람 |
| `c` | word | 코드(§6) |
| `d` | word | 짧은 세부(선택, ≤ 40자). 예: `TH0+D9`(UV 조건 중 못 채운 것), `FORK_WAFER/ng/3`, `+5.0/-0.00`(δr/δθ) |
| `stp` | word | 단계 키(선택) |
| `n` | int | ① 슬롯(선택) |
| `k` | int | ③ 슬롯(선택) |
| `w` | int | 웨이퍼 번호(선택) |
| `s` | word | 대차 받침(선택) |

한글 문장은 PC(`texts.py`)가 코드와 세부에서 만듭니다. Mega는 한글을 보내지 않습니다.

| 키 | 종류 | 뜻 |
|---|---|---|
| `id` | int | 촬영 id(매번 새로) |
| `n` | int | ① 슬롯 |
| `w` | int | 웨이퍼 번호 |

| 키 | 종류 | 뜻 |
|---|---|---|
| `id` | int | 받은 `CMD`의 id |
| `ok` | bool | 받아들임 |
| `e` | word | 거부 이유: `bad_state` · `estop` · `not_homed` · `cell_not_clear` · `unknown` · `bad_arg` · `busy`. 받아들였으면 `-`. |
| `st` | word | 처리한 뒤 상태 |

## 3. PC → Mega

### `HB` — 하트비트 (0.5 s마다)

| 키 | 종류 | 뜻 |
|---|---|---|
| `t` | int | PC 순번 |

**하트비트가 1.5 s 끊기면** Mega는 다음과 같이 합니다.
1. UV 램프를 **바로** 끕니다.
2. 지금 하던 축 동작(θ/Z/R 한 번)만 끝내고 `PAUSED`(`pr=LINK`)가 됩니다.
3. 하트비트가 다시 와도 스스로 재개하지 않습니다. 사람이 `resume`을 보내야 합니다.

첫 `HB`를 받기 전(IDLE)에는 이 규칙을 적용하지 않아도 됩니다.

### `CMD` — 운전 명령

| 키 | 종류 | 뜻 |
|---|---|---|
| `id` | int | 1–65535(PC가 매번 새로 매김) |
| `c` | word | `hello` · `home` · `start` · `pause` · `resume` · `stop` · `reset` |
| `x` | word | PC가 본 상태(선택). Mega의 지금 상태와 다르면 실행하지 않고 `ACK ok=0 e=bad_state`로 답합니다(화면이 늦게 갱신된 채 누른 버튼을 막으려고). |

- **중복:** Mega는 최근 id 8개를 기억합니다. 같은 id가 다시 오면 **실행하지 않고** 지난번과 같은 `ACK`를 다시 보냅니다.
- PC는 연결이 끊겼다 다시 붙어도 명령을 다시 보내지 않습니다.
- PC는 `ACK`를 1 s 기다립니다. 응답이 없으면 화면에 '장비 응답 없음'을 띄웁니다.
- 명령별 허용 상태(시뮬과 같게):

| 명령 | 허용 상태 | 거부 이유 |
|---|---|---|
| `home` | IDLE, READY | `estop`(D9 끊김) |
| `start` | READY | `not_homed`, `cell_not_clear`(포크/크래들/UV 받침에 웨이퍼, 포크에 카세트) |
| `pause` | HOMING, RUNNING, WAIT_CART, WAIT_NG | |
| `resume` | PAUSED | `estop` |
| `stop` | HOMING, RUNNING, WAIT_CART, WAIT_NG, PAUSED | → IDLE, 원점 미확정 |
| `reset` | ALARM, ESTOP | ESTOP은 D9가 돌아와야 합니다. 원점 복귀가 필요 없는 알람은 PAUSED(재개 대기)로, 원점 복귀가 필요한 알람은 IDLE로 갑니다. |

### `JDG` — 판정 (`CAP`에 대한 답)

| 키 | 종류 | 뜻 |
|---|---|---|
| `id` | int | `CAP`의 id. 지금 기다리는 id가 아니면 Mega는 버립니다. |
| `r` | word | `OK` · `NG` · `ERR`(카메라/판정 실패 → `CAMERA` 알람) |
| `dr` | float | 치우침 δr mm. 다시 집기 RX = 51 + δr. |
| `dt` | float | 치우침 δθ deg. 다시 집기 θ = 120 + δθ. |

- Mega는 `CAP`를 보낸 뒤 **5 s 안에** `JDG`가 오지 않으면 `JUDGE_TIMEOUT` 알람을 냅니다.
- 보정 창은 **δr −3.5 ~ +0.5 · |δθ| ≤ 0.5**입니다. 창 밖이면 `CORR_RANGE` 알람을 냅니다.
- 촬영은 최소 0.5 s(백라이트 점등 + 촬영)를 지켜야 합니다.
- 판정 알고리즘은 아직 [미구현]입니다. 지금 PC는 기본값 OK · δ 0을 보내고, 화면의 '다음 웨이퍼 NG' 버튼으로 NG를 지정합니다.

## 4. 상태 `st`

`IDLE` 원점 필요 · `HOMING` · `READY` · `RUNNING` · `WAIT_CART` 대차 대기 · `WAIT_NG` 불량 카세트 가득/없음(교체 요청) · `PAUSED` · `ALARM` · `ESTOP`

- **③ 교체:** TOF-NG가 '없음 → 있음'으로 바뀌면 새 빈 카세트로 보고 `ng`를 0으로 합니다.
- **UV 램프 켜기:** 7가지 조건을 모두 채울 때만 켭니다. 못 채우면 `UV_INTERLOCK`(`d`에 못 채운 항목을 `+`로 이어 붙임).
  - `TH0`: θ0 센서 LOW
  - `ANGLE`: θ 0 ± 0.2°
  - `RX`: RX ≤ 2(R Sharp)
  - `ZC`: ZC ≤ 110
  - `HAND`: 받침에 넘김(U4 뒤 U5에서 S4 ON → OFF)
  - `JUDGE`: 판정 OK
  - `D9`: E-stop 사슬 살아 있음
- **A_UV:** 켠 뒤 0.3 s 안에 창 안이어야 합니다. 아니면 `UV_FAULT`. 조사 중에 꺼지면 `UV_LOST`(KSD9700 과열 또는 LED).
- **일시정지 · 비상 · 링크 끊김:** UV를 끄고, 재개하면 그 조사를 **처음부터** 다시 합니다.

## 5. 단계 키 `stp` (화면 타임라인 · 문구와 같아야 함 = `sequence.step_keys()`)

동작 기호:
- `rot` 선회. `[side]`는 옆길 180↔220이고 RX ≤ 2에서만 합니다. `[carry]`는 카세트를 든 180↔270이고 Z241에서만 합니다. `[fine]`은 ② Z183에서 δθ만 돌립니다.
- `z` · `r` 이동
- `vz` · `vr` Sharp로 확인(±3 mm, 가정)
- `ret` R Sharp RX ≤ 2
- `expect_th` 그 자리 θ 센서만 LOW
- `expect` S4/TOF
- `check_pick` P3 S4. ON이면 꺼냄, OFF이면 `E1` 빈 슬롯.
- `capture` `CAP`/`JDG`
- `uv` 조사
- `home_z` · `home_th` 원점

| 키 | 묶음 | 화면 문구 | 동작 순서 |
|---|---|---|---|
| `H1` | 원점 · 대기 | 원점 — R 후진 | r -2 · ret |
| `H2` | 원점 · 대기 | 원점 — Z 선회 높이 (Z Sharp) | home_z · z 105 · vz |
| `H3` | 원점 · 대기 | 원점 — θ 자리 찾기 | home_th |
| `H4` | 원점 · 대기 | 대기 (θ120 · Z 105 · R 후진) | rot 120 · expect_th inspect |
| `C1` | 대차 -> ① | 대차 받침으로 선회 | rot 270 · expect_th cart |
| `C2` | 대차 -> ① | 받침 카세트 밑으로 포크 | z 205 · vz · r 85 · vr |
| `C3` | 대차 -> ① | 카세트 들기 -> 빼기 | z 241 · vz · r -2 · ret |
| `C4` | 대차 -> ① | 든 채 ① 로 선회 (270 -> 220 -> 180) | expect TOF_IN · rot 180 [carry] · expect_th input |
| `C5` | 대차 -> ① | ① 도크에 내려놓기 | r 73 · vr · z 228.5 · vz · r -2 · ret · expect TOF_IN · z 105 |
| `P1` | ① 꺼내기 | ① 투입 (180°) 으로 선회 | rot 180 · expect_th input · expect TOF_IN |
| `P2` | ① 꺼내기 | ① 슬롯 n 밑으로 포크 | z 121.5 · vz · r 73 · vr |

**흐름:**
1. 원점: H1 → H4
2. 대차 → ①: C1 → C5
3. 웨이퍼마다(① 슬롯 1 → 5): P1 → P3 → I1 → I4. 단, P3에서 S4가 없으면 E1로 갑니다.
   - 불량이면 N1 → N2
   - 정상이면 U1 → U7 → R1 → R5
4. 5장이 끝나면 L1 → L7. 그다음 대차가 다음 받침으로 움직이거나, 다 처리했으면 출발합니다. 새 대차가 오면 다시 C1부터.
5. `W`는 대기 자세로 돌아가는 단계입니다.

**선회 규칙:**
- 기본은 Z105 · RX ≤ 2입니다.
- 예외는 셋입니다.
  - 옆길: θ180↔220, 그 높이 그대로, RX ≤ 2
  - 카세트 운반: θ180↔270, Z241, RX ≤ 2
  - ② 미세 회전: Z183, 0.5° 이하
- **① 앞에서 웨이퍼를 든 채로 Z를 움직이지 않습니다.** 후진한 운반 웨이퍼가 아래 슬롯 웨이퍼와 반경 27 mm 겹치기 때문입니다. 옆길 θ220에서 높이를 바꿉니다.
- 빈 포크는 ① 앞에서 바로 오르내릴 수 있습니다(포크 끝 R ≤ 205, ① 웨이퍼는 207.5부터).

## 7. 실장비에서 확인할 것 [불명]

- **포트 열기 리셋:** 포트를 열 때 Mega가 리셋되므로, 화면을 다시 열거나 서버를 다시 시작하면 공정이 처음 상태로 돌아갑니다.
  - 공정 중에는 서버를 끄지 마세요.
  - 리셋을 막으려면 하드웨어 방법이 있습니다: RESET–GND 10 µF 또는 DTR 선 끊기. 그러면 업로드할 때 수동 리셋이 필요합니다.
- **보정값 [실측]:** Sharp 환산식, θ 센서 ±1.65°, A_UV 문턱, TOF-IN 문턱(R22에서 ① 도크를 22 mm 옮겼으므로 다시 티칭)은 모두 실측으로 정해야 합니다. 이 문서의 허용값(±3 mm 등)은 가정입니다.
- **공정 중 정지 뒤 재시작:** 셀 안에 웨이퍼가 남은 채로 다시 시작하는 규칙은 펌웨어 단계에서 정해야 합니다. 지금 시뮬은 `cell_not_clear`로 시작을 거부하고, 시뮬 도구로만 치울 수 있습니다. 실장비 명령 6개에는 '손으로 치웠음'을 알리는 명령이 없습니다.
- **직렬 대역 · 타이밍 [불명]:** `ST` 한 줄은 약 150~190 B이고, 115200 bps에서 13~17 ms 걸립니다. 20 Hz면 링크의 약 30 %를 씁니다. Mega TX 버퍼(64 B)가 차면 `Serial.print`가 멈추므로 다음을 지켜야 합니다.
  - 스텝 펄스(Z)와 θ 이동은 타이머 인터럽트로 만듭니다.
  - 송신은 `Serial.availableForWrite()`를 보고 나눠서 보냅니다.
  - 그래도 부족하면 `ST`를 10 Hz로 낮춥니다. PC는 `STALE_S` 1 s 안에만 오면 됩니다.
